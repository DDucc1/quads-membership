# 홀덤 포스터 하네스 (Hold'em Poster Harness)

> "레퍼런스를 그냥 주면 결과가 뒤죽박죽"인 문제를 구조적으로 제거하기 위한 시스템.
> **게임 내용(JSON)** 만 넣으면 → 레퍼런스 12종에서 추출한 **고정 규격(하네스)** 과
> **응용 규칙** 이 자동 적용되고 → **평가모델(QA 게이트)** 을 100% 통과한 결과만 최종 포스터로 산출.

---

## 0. 왜 하네스인가 (문제 정의)

기존 방식: `레퍼런스 이미지 + "이런 느낌으로 만들어줘"`
→ 모델이 매번 레이아웃·여백·폰트·정렬을 새로 추측 → **글자 겹침/넘침/엇나감, 품질 편차** 발생.

하네스 방식: 생성 자유도를 **3개 레이어로 분리**해서 통제한다.

```
[LAYER 1] 골격(SKELETON)   ── 절대 변하지 않음. 밴드/그리드/세이프존/정렬 규칙.
[LAYER 2] 스타일 토큰(TOKEN) ── 테마별로 값만 바뀜. 컬러/폰트웨이트/명암/글로우.
[LAYER 3] 콘텐츠 바인딩(BIND) ── 게임마다 바뀜. 텍스트/숫자/이미지 소재.
```

핵심 명제: **레이아웃은 절대 즉흥적으로 만들지 않는다.** 입력이 골격에 "바인딩"될 뿐이다.

## 1. 파이프라인 (생성 흐름)

```
 게임내용(JSON)
      │
      ▼
[STEP 1] 아키타입 라우터 ──────────► A(단일이벤트) / B(스트럭처시트) / C(시리즈스케줄)
      │
      ▼
[STEP 2] 골격 주입(SKELETON)  ── 03_fixed-vs-flexible.md 의 FIXED 규칙 = 절대 고정
      │
      ▼
[STEP 3] 스타일 토큰 선택      ── 테마(불/물/우주/동물/도어…) → 컬러·폰트·명암 토큰
      │
      ▼
[STEP 4] 콘텐츠 바인딩         ── 입력 텍스트/숫자를 밴드별 슬롯에 채움 (오토 폰트축소)
      │
      ▼
[STEP 5] 렌더
      │
      ▼
[STEP 6] 평가모델 게이트 ───── 04_evaluation-rubric.md (전 항목 PASS 필수)
      │            │
   PASS │      FAIL │ → 리페어 루프(원인 항목만 수정) → STEP 5 재진입
      ▼
  최종 포스터 ✅
```

**불변 원칙:** STEP 6에서 단 한 항목이라도 FAIL이면 그것은 "초안"이며 **최종 포스터가 아니다.**

## 2. 파일 구성

| 파일 | 역할 | 레이어 |
|---|---|---|
| `01_master-prompt.md` | 강화된 시스템 프롬프트(엔진 본체). 이미지 모델에 그대로 투입. | 전체 |
| `02_reference-analysis.md` | 레퍼런스 12종 × 각 30+ 디테일 포인트 추출 원장. | 근거 |
| `03_fixed-vs-flexible.md` | 추출 포인트를 **고정 하네스 vs 응용** 으로 분류. | L1 / L2·L3 |
| `04_evaluation-rubric.md` | 평가모델(QA 게이트). 합격 기준·감점·자동 리젝트. | QA |
| `05_first-draft-demo.md` | 임의 게임내용으로 만든 1차 초안 스펙(A/B/C 각 1종). | 데모 |
| `schema/game-input.schema.json` | 게임내용 입력 표준 스키마. | 입력 |

---

## 3. 사용법 (운영자 관점)

1. `schema/game-input.schema.json` 형식으로 게임 내용을 채운다. (텍스트만 신경 쓰면 됨)
2. `01_master-prompt.md` 전문 + 입력 JSON 을 이미지 생성 모델에 함께 투입한다.
3. 산출물을 `04_evaluation-rubric.md` 체크리스트로 검수한다.
4. 전 항목 PASS → 배포. 1개라도 FAIL → 해당 항목만 리페어 후 재검수.

---

## 4. 좌표계 공통 약속 (요구사항 #1 — 겹침/넘침/엇나감 0%)

- 마스터 캔버스: **세로형, 3:5 기준(예 1080×1800px).** B/C는 3:5~9:16 허용.
- **세이프존:** 좌우 각 6%, 상단 3%, 하단 3%. 어떤 글자도 세이프존 바깥으로 못 나간다.
- 레이아웃은 **수평 밴드(band)** 의 스택으로만 구성. 밴드끼리 **세로 겹침 금지**, 밴드 사이 최소 갭 ≥ 2%H.
- 모든 텍스트는 소속 밴드의 **앵커(center/left/right)** 중 하나에 정렬. 자유 배치 금지.
- 텍스트가 밴드 폭을 넘기면 **임의 줄바꿈/탈출 금지** → 폰트 스텝 다운(95%→90%→…→최저 70%) 후에도 안되면 약어/2줄 규칙 적용.

자세한 수치는 `01_master-prompt.md` 의 GRID SPEC 참조.
