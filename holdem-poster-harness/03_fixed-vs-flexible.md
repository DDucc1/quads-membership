# 03 — 고정 하네스(FIXED) vs 응용(FLEXIBLE) 분류

> 요구사항 #4: 추출 포인트를 "무조건 지켜야 할 고정 하네스"와 "유연하게 응용·수정할 포인트"로 분류.
> 12종 레퍼런스가 **테마·금액·표 내용은 제각각이어도 골격은 동일**하다는 사실이 분류의 근거다.
> (예: REF-03/04 = 같은 골격, 소재만 호랑이↔고양이 / REF-08/09/11 = 같은 B골격, 금액·표만 다름)

---

## PART 1 — FIXED HARNESS (절대 고정, 변경 시 = 하네스 위반)

이 항목들은 **모든 포스터에서 동일하게 강제**된다. 입력과 무관하게 엔진이 보장한다.

### F-A. 레이아웃 골격
- **F-A1** 밴드 수직 스택 구조 + 밴드 간 세로 겹침 금지(갭 ≥ 2%H). *(전 레퍼런스 공통)*
- **F-A2** 세이프존: 좌우 6% / 상하 3%. 어떤 요소도 침범 불가.
- **F-A3** 텍스트는 밴드 앵커(좌/중/우)에만 정렬. 자유배치 금지.
- **F-A4** 밴드 순서(아키타입별):
  - A: `로고 → 타이틀 → GTD → 일시·장소 → BUY-IN → 스탯4열 → Notice → 스폰서바 → 푸터`
  - B: `로고/시리즈뱃지 → 타이틀 → GTD/시드 → 일시·브랜드 → BUY-IN/스탯 → (프라이즈표|스탯리스트) + 블라인드표 → Notice → 스폰서/푸터`
  - C: `로고 → 시리즈타이틀 → 기간 → 총보증 → 스케줄그리드 → 스폰서/푸터`

### F-B. 정보 블록 (반드시 존재)
- **F-B1** 스탯은 항상 **ENTRY/STARTING/LATE REG/BLIND**(A) 또는 **STACK/END of REG/DURATION/ENTRY**(B)의 4항목 라벨 체계.
- **F-B2** "BUY-IN" 라벨 + 티켓조건 블록은 필수.
- **F-B3** "⚠️ Notice for Player" 박스 + 좌정렬 불릿 필수.
- **F-B4** 하단 스폰서 바 = **주관사 / 협력사 / 후원사 / 장소** 4구역 라벨 체계.
- **F-B5** 최하단 장소 푸터 = 지점명 + 도로명 주소.
- **F-B6** B/C 아키타입은 우상단 **시리즈 뱃지 + TOTAL GUARANTEED** 필수.

### F-C. 타이포 규칙
- **F-C1** 영문 디스플레이 폰트 ↔ 한글 고딕 폰트 **역할 분리**.
- **F-C2** role별 크기/두께 위계 고정(DISPLAY > DISPLAY-SUB > H1 > H2 > STAT > BODY > CAPTION).
- **F-C3** GTD/금액 = 숫자 큼 + `GTD` 첨자 작게 + 천단위 콤마. 단위·포맷 일관.
- **F-C4** 스탯 셀 = 상단 작은 라벨 + 하단 굵은 값 2행.
- **F-C5** 표(B/C) 숫자는 정렬·천단위 콤마·통화기호 일관. 셀 텍스트 줄바꿈 금지.

### F-D. 표(스트럭처/그리드) 골격
- **F-D1** B 블라인드표는 **2-컬럼 레벨 그룹** + 각 그룹 상단 헤더(LV·SB·BB·ANTE·BLIND) 반복.
- **F-D2** BREAK/REMOVE/END of REG/T.D DECISION = **풀폭 강조 행**.
- **F-D3** C 스케줄 그리드는 날짜별 행 그룹 + 그룹 구분선 + zebra 가독.

### F-E. 브랜딩
- **F-E1** 상단 POD 로고 + "POKER of DREAMS" 워드마크.
- **F-E2** 스폰서 로고는 단색 정규화 + 높이 통일 한 줄 정렬.

## PART 2 — FLEXIBLE / APPLICATION (게임마다 응용·수정)

입력 JSON에 따라 **값/소재만** 바뀐다. 골격은 절대 건드리지 않는다.

### V-1. 테마·비주얼 (자유도 高)
| 항목 | 가변 범위 | 근거 레퍼런스 |
|---|---|---|
| 배경 소재 | 불꽃/바다/우주/맹수/우드/추상광 등 무제한 | REF 01~12 전부 다름 |
| 팔레트 | flame_blue/golden_door/ocean_teal/space_blue/animal_dark/wood_warm/series_* | 9개 프리셋 |
| 타이틀 텍스처 | 솔리드/메탈릭/그라데이션/아웃라인 | REF-02 메탈, REF-05 아웃라인 |
| 광원 위치 | 중앙/상단/대각선 | REF-01 중앙, REF-08 대각 |

### V-2. 타이틀 카피 (구조는 고정, 문구는 가변)
- 이벤트명: `CHALLENGE` / `Collaboration` / `MAIN EVENT` / `SATELLITE` / `HIGH-ROLLER` …
- 포맷 프리픽스: `8 MAX` / `9 MAX`(옵션, 있으면 타이틀 선두).
- 회차/지명 결합: `Chapter.4`, `in 영주`, `대전→전주` 등(옵션 악센트).
- 보상 표기: `00,000,000 GTD` ↔ `WIN YOUR SEAT @160,000`(새틀라이트) 택1.

### V-3. 수치/콘텐츠 (전량 입력 바인딩)
- GTD/총보증 금액, ENTRY 수(`72`/`955++`/`8 TO 1`), STARTING(50,000/60,000/80,000),
  LATE REG/END of REG 레벨, BLIND/DURATION(`25 Mins`/`25/20 Mins`/`40/30Mins`/TURBO),
  날짜·시간(자연어형 ↔ 숫자형 둘 다 허용), 지점명·주소.

### V-4. 티켓/결제 옵션 (행 개수 가변)
- `1 Challenge Ticket` (단일) ↔ `1 Challenge OR 20PP OR 20FP` (다중) ↔ `20 SEED`(새틀라이트).
- 다중 OR 옵션도 한 행에 안정 배치(F-A3 유지).

### V-5. Notice 불릿 (개수 가변, 헤더는 고정)
- 공통행(레지스트레이션/빅블라인드엔티/TDA/부정행위/9max/S-Ticket/신분증/세금/뉴플레이어카드)은 풀(pool)에서 선택.
- 이벤트 전용행(타임뱅크/콜라보 PP·FP/새틀라이트 좌석규칙 등)은 입력 시 추가.

### V-6. B/C 표 콘텐츠 (구조 고정, 내용 가변)
- 블라인드 레벨 수, 앤티 시작 레벨, 브레이크 위치/길이, REMOVE 칩 시점.
- 프라이즈표 유무(REF-10은 없음) 및 등수·금액.
- 스케줄 그리드 행 수/이벤트 종류(C).

### V-7. 옵션 밴드 (있으면 표시, 없으면 제거 후 재균등)
- 트로피 뱃지(A0): REF-05엔 없음 → 옵션.
- 콜라보 파트너 락업(REF-03/04): 콜라보 입력 시만.
- EUREKA 등 제휴 엠블럼(REF-08): 제휴 입력 시만.

## PART 3 — 분류 판정 규칙 (경계 사례)

응용처럼 보이지만 **사실은 고정**인 함정:
- 테마는 자유지만 **"텍스트 가독을 위한 국소 음영/대비 확보"는 고정**(품질). → `04_rubric` Q항목.
- 티켓 문구는 자유지만 **"BUY-IN 라벨 위치·앵커"는 고정**.
- 표 내용은 자유지만 **"헤더 반복·BREAK 강조행·콤마 포맷"은 고정**.

고정처럼 보이지만 **사실은 응용**인 함정:
- 스탯 "4열"은 고정 라벨체계지만, **값이 없는 열은 제거 후 3열/2열 재균등**(빈칸 금지)이 우선.
- Notice "불릿"은 고정 블록이지만 **행 개수·전용행은 가변**.

## 한 줄 요약
> **골격·정보블록·타이포위계·표구조·브랜딩 = FIXED.**
> **테마·카피문구·수치·티켓옵션·Notice행·표내용·옵션밴드 = FLEXIBLE.**
> 운영자는 FLEXIBLE만 입력하고, 엔진은 FIXED를 강제하며, 품질(Q)은 `04_rubric`이 게이트한다.
